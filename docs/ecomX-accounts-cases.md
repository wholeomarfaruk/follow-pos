# PART 3 — প্রতিটা Feature-এর Case + Journal Entry

> প্রতিটা case-এ: **কী হলো → frontend-এ কী দেখাবে → backend journal → ফলাফল**

---

## 🔄 লেনদেন (Transactions)

### Case 1.1 — Manual Income (হাতে আয় বসানো)
**কী:** পুরনো এক কাস্টমার নগদে ৳১০,০০০ দিলো (order-এর বাইরে)।
```
Dr  নগদ            ৳10,000
    Cr  অন্যান্য আয়        ৳10,000
```
**ফলাফল:** নগদ বাড়লো, আয় বাড়লো → লাভে যোগ হবে।

### Case 1.2 — Manual Expense
**কী:** বিকাশ থেকে ৳৫,০০০ ফেসবুক অ্যাড।
```
Dr  অ্যাড খরচ        ৳5,000
    Cr  বিকাশ             ৳5,000
```

### Case 1.3 — Transfer (fee ছাড়া)
**কী:** ক্যাশ থেকে ব্যাংকে ৳৫০,০০০।
```
Dr  ব্যাংক          ৳50,000
    Cr  নগদ              ৳50,000
```
**নোট:** এটা income/expense না — শুধু জায়গা বদল। লাভে প্রভাব নাই।

### Case 1.4 — Transfer + Fee ⭐ (বিকাশ→ব্যাংক ২০ টাকা fee)
**কী:** বিকাশ থেকে ব্যাংকে ৳২,০০০ পাঠালাম, ২০ টাকা fee কাটল।
**frontend:** টাকা ২০০০, fee ২০ → দুইটা ঘর।
```
Dr  ব্যাংক          ৳2,000
Dr  ট্রান্সফার চার্জ   ৳20
    Cr  বিকাশ             ৳2,020
```
**ফলাফল:** বিকাশ থেকে মোট ৳২,০২০ গেল, ব্যাংকে ঢুকল ৳২,০০০, ২০ টাকা খরচ (P&L)।

### Case 1.5 — ডলার/কারেন্সি কেনা + Fee ⭐
**কী:** বিকাশের ৳১২,২০০ দিয়ে $১০০ কিনে কার্ডে লোড। রেট ৳১২০/$, fee ৳২০০।
**frontend:** কত টাকা দিলাম (12,200), কত ডলার পেলাম (100), fee (200)।
```
Dr  ডলার কার্ড       ৳12,000   ($100 @ ৳120)
Dr  কনভার্সন fee     ৳200
    Cr  বিকাশ              ৳12,200
```
**ফলাফল:** ডলার কার্ডে $১০০ (৳১২,০০০ সমমান), ২০০ টাকা fee খরচ।
**নোট:** ডলার কার্ড আলাদা account, balance ডলারে রাখো। পরে রেট বদলালে FX gain/loss ধরতে হবে (advanced)।

### Case 1.6 — লেনদেন এডিট (Golden Rule) ⭐
**কী:** ৳৫,০০০ অ্যাড খরচ ভুল করে ৳৫,০০০ লেখা, আসলে ৳৭,০০০।
**নিয়ম:** posted entry কখনো সরাসরি বদলাবে না — পুরনোটা reverse করে নতুন বসবে।
```
Step 1 (reverse পুরনো):
Dr  বিকাশ           ৳5,000
    Cr  অ্যাড খরচ         ৳5,000

Step 2 (নতুন post):
Dr  অ্যাড খরচ        ৳7,000
    Cr  বিকাশ             ৳7,000
```
**হিস্ট্রি:** created → reversed → reposted (সব থাকবে)।

### Case 1.7 — Void (বাতিল)
**কী:** একটা posted খরচ পুরো বাতিল।
```
Dr  বিকাশ           ৳5,000
    Cr  অ্যাড খরচ         ৳5,000   (উল্টো entry — delete না)
```
**নিয়ম:** Draft হলে delete করা যাবে; Posted হলে শুধু Void/Reverse।

## 💵 হাতে আছে (Cash & Bank)

### Case 2.1 — নতুন অ্যাকাউন্ট (opening সহ)
**কী:** নতুন "City Bank" account, শুরুর জমা ৳১,০০,০০০।
```
Dr  City Bank        ৳1,00,000
    Cr  Opening Balance Equity   ৳1,00,000
```

### Case 2.2 — Bank Reconciliation (মিলানো)
**কী:** ব্যাংক statement-এ ৳৫০,০০০, তোমার বইয়ে ৳৪৮,০০০ — ২,০০০ পার্থক্য (একটা fee ধরা হয়নি)।
- মিলানোর screen-এ unmatched item দেখাবে।
- ২,০০০ ব্যাংক চার্জ entry দিলে:
```
Dr  ব্যাংক চার্জ      ৳2,000
    Cr  ব্যাংক              ৳2,000
```
- এখন বই = statement = ৳৫০,০০০। Entry গুলো "Reconciled" mark হবে।

## 📥 আমি পাবো (Receivable)

### Case 3.1 — বিক্রি হলে receivable তৈরি (COGS সহ, perpetual) ⭐
**কী:** ৳৫,০০০-এর অর্ডার, পণ্যের কেনা দাম ৳৩,০০০। বাকিতে।
```
বিক্রি রেকর্ড:
Dr  আমি পাবো (AR)    ৳5,000
    Cr  বিক্রি (Sales)      ৳5,000

COGS রেকর্ড (একই সময়ে):
Dr  পণ্যের কেনা দাম (COGS)  ৳3,000
    Cr  স্টক (Inventory)          ৳3,000
```
**ফলাফল:** পাবো ৳৫,০০০, স্টক ৳৩,০০০ কমল, gross লাভ ৳২,০০০।
**⚠️ জরুরি:** প্রতিটা বিক্রিতে COGS entry লাগবে — নাহলে লাভ ভুল আসবে।

### Case 3.2 — পুরো টাকা পেলাম
**কী:** উপরের কাস্টমার ৳৫,০০০ বিকাশে দিলো।
```
Dr  বিকাশ            ৳5,000
    Cr  আমি পাবো (AR)      ৳5,000
```

### Case 3.3 — আংশিক টাকা পেলাম
**কী:** ৳৫,০০০-এর মধ্যে ৳২,০০০ দিলো।
```
Dr  বিকাশ            ৳2,000
    Cr  আমি পাবো          ৳2,000
```
**ফলাফল:** এখনো ৳৩,০০০ বাকি।

### Case 3.4 — এক পেমেন্ট → একাধিক বিল (Allocation) ⭐
**কী:** কাস্টমার রহিম ৳১০,০০০ দিলো — Invoice #1 (৳৪,০০০) আর #2 (৳৬,০০০) শোধ।
```
Dr  বিকাশ            ৳10,000
    Cr  আমি পাবো          ৳10,000
```
**Allocation table:**
```
Payment #P-100 → Invoice #1 : ৳4,000
Payment #P-100 → Invoice #2 : ৳6,000
```
**ফলাফল:** দুই invoice-ই পুরো পরিশোধ।

### Case 3.5 — Overdue
**কী:** Invoice #5 এর due date ৭ দিন পার, ৳৩,০০০ বাকি।
- কোনো নতুন journal না — শুধু status "Overdue", হোম-এ সতর্কতা দেখাবে।

### Case 3.6 — রিটার্ন / RTO (পণ্য ফেরত) ⭐
**কী:** ৳৫,০০০-এর ডেলিভার্ড অর্ডার কাস্টমার ফেরত দিলো, পণ্য বিক্রিযোগ্য (কেনা দাম ৳৩,০০০)।
```
বিক্রি উল্টানো:
Dr  বিক্রি ফেরত (Sales Return)   ৳5,000
    Cr  আমি পাবো / রিফান্ড           ৳5,000

স্টক ফেরত:
Dr  স্টক (Inventory)      ৳3,000
    Cr  পণ্যের কেনা দাম (COGS)  ৳3,000
```
**RTO আলাদা (deliver হয়নি):** পণ্য কখনো কাস্টমারের হাতে যায়নি → শুধু স্টক ফেরত + কুরিয়ার return fee খরচ:
```
Dr  কুরিয়ার খরচ       ৳80
    Cr  কুরিয়ার COD / বিকাশ    ৳80
```
(বিক্রি recognize না হলে sales reversal লাগবে না — শুধু fee।)

### Case 3.7 — রিফান্ড (টাকা ফেরত)
**কী:** কাস্টমারকে ৳৫,০০০ বিকাশে ফেরত।
```
Dr  বিক্রি ফেরত / রিফান্ড   ৳5,000
    Cr  বিকাশ                   ৳5,000
```

### Case 3.8 — কাস্টমার ক্রেডিট: পরের অর্ডারে adjust ⭐
**কী:** কাস্টমার ৳৭,০০০ দিয়েছিল, অর্ডার ৳৫,০০০ — ৳২,০০০ বেশি (ক্রেডিট)।
```
বেশি টাকা:
Dr  বিকাশ            ৳7,000
    Cr  আমি পাবো          ৳5,000
    Cr  কাস্টমার ক্রেডিট     ৳2,000

পরের অর্ডার ৳2,000 (ক্রেডিট দিয়ে):
Dr  কাস্টমার ক্রেডিট   ৳2,000
    Cr  বিক্রি              ৳2,000
```
**ফলাফল:** কোনো ক্যাশ বের হলো না, জমা টাকা ব্যবহার হলো। (এটাই ব্যবসার জন্য ভালো।)

### Case 3.9 — কাস্টমার ক্রেডিট: টাকা ফেরত
**কী:** কাস্টমার আর কিনবে না, ৳২,০০০ ক্রেডিট ফেরত চায়।
```
Dr  কাস্টমার ক্রেডিট   ৳2,000
    Cr  বিকাশ              ৳2,000
```
**নোট:** এটা refund, খরচ না, মালিকের উত্তোলনও না — শুধু জমা দায় মিটল।

### Case 3.10 — বাকি মাফ (Bad Debt)
**কী:** কাস্টমার ৳৩,০০০ কখনো দেবে না (পালিয়ে গেছে / COD হারিয়ে গেছে)।
```
Dr  বাকি মাফ খরচ (Bad Debt)   ৳3,000
    Cr  আমি পাবো                   ৳3,000
```
**ফলাফল:** পাবো থেকে বাদ, খরচ হিসেবে লাভ কমল।

### Case 7.3 — সম্পদ বিক্রি (ক্ষতি সহ)

**লাভে বিক্রি হলে (৳৩৫,০০০):** Loss-এর জায়গায় Cr "Gain on Disposal ৳5,000"।

# PART 4 — Golden Rules (মনে রাখার মতো)

1. **Double-entry সবসময়:** প্রতিটা entry-তে Debit = Credit।
2. **Posted কখনো delete না:** এডিট হলে reverse + repost; বাতিল হলে Void। Draft হলে delete ঠিক আছে।
3. **প্রতিটা বিক্রিতে COGS:** স্টক কমাও, নাহলে লাভ ভুল।
4. **আসল ≠ সুদ:** ঋণের কিস্তিতে আসল দায় কমায়, সুদ খরচ।
5. **মালিকের টাকা income/expense না:** Investment = equity বাড়ে, Withdrawal = equity কমে; P&L-এ আসে না।
6. **সব fee track করো:** transfer/gateway/conversion — লুকানো খরচ ধরা পড়বে।
7. **Closed period-এ সরাসরি হাত না:** reverse চলতি খোলা মাসে বসবে।
8. **Duplicate আটকাও:** একই event দুইবার post হলে টাকা double হবে — unique key দাও।
9. **Frontend সহজ, backend পূর্ণ:** ব্যবসায়ী "টাকা পেলাম" চাপে, backend double-entry বানায়।
